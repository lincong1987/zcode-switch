# zcode-switch Upstream 1.5.3 Fusion and Render Deduplication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or **superpowers:executing-plans** to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Merge \`pjpv/zcode-switch\` v1.5.3 into the local feature line, retain local account/model/claim/UI changes, stop redundant periodic full redraws, and make Windows build artifacts consistently versioned.

**Architecture:** Keep the existing five-second state poll because it detects external file edits and ZCode process changes, but compare each returned state with a deterministic fingerprint and render only when it changes. Reuse the same change gate for \`state-changed\` events and model-config refreshes; explicit user actions may still render immediately. Keep the stable runtime/CLI executable name \`zcode-switch.exe\`, while the distribution script emits versioned installer and portable filenames.

**Tech Stack:** Tauri 2, Rust, vanilla ES modules, Vite, Node.js build scripts, Cargo tests, Node built-in test runner.

**Spec:** User request in the current task (2026-09-05).

- [ ] **Step 3: Implement recursive canonical serialization.**

Create \`src/state-fingerprint.js\`:

~~~js
function canonicalize(value) {
  if (Array.isArray(value)) return value.map(canonicalize);
  if (value && typeof value === "object") {
    return Object.fromEntries(Object.keys(value).sort().map((key) => [key, canonicalize(value[key])]));
  }
  return value;
}

export function stateFingerprint(value) {
  return JSON.stringify(canonicalize(value));
}
~~~
